okay so here's my rough plan for reedbed

the protocol will be called katare. one protcol message is a kata. URI form katare://host[:440]/<package>

TCP port 440. server speaks first, request-response, one in flight at a time

CRLF-terminated lines <= 1024 bytes including CRLF, tokens separated by a single SP

first token is the verb (requests) or the status (responses). a line whose final two tokens are kyx <n> is followed immediately by exactly n octets of opaque body, no terminator. default cap is 64 MiB but is server-configurable and advertised

all keywords are lowercase ASCII, case-sensitive (we use zh/gh rather than ž/ǧ)

unlike batelu, numbers on the wire are decimal ASCII

reads will be prefixed ko, writes won't

ko jexa <query...>              read
ko besal <izim> [<waktanimra>]  read
ko ghazema <izim> <waktanimra>  read
ko cizujo <izim> <constraint>   read
kalit / kango / kaldy / koja    write or session control

so a parser can therefore classify a request before it knows the verb, and a read-only mirror can reject anything not starting with ko.

the handshake

S: dijabon katare/1 <server-izim>
C: dijabon katare/1 <client-izim>            e.g. oboe/0.1
S: si <capability>...                        e.g. si jexa cizujo kango sema

capabilities are bare words naming the optional verbs/features the server supports. this is the extension mechanism

verbs

Request Meaning Success response
ko jexa <query...> search si kyx <n> + record body (0 matches is si kyx 0, not an error)
ko besal <izim> package metadata, all releases si kyx <n> + records
ko besal <izim> <waktanimra> one release's metadata si kyx <n> + one record
ko ghazema <izim> <waktanimra> fetch the archive si <sema> kyx <n> + kabuk octets
ko cizujo <izim> <constraint> server-side dependency resolution (optional capability) si kyx <n> + flat resolved set, one <izim> <waktanimra> <sema> per line
kalit <token> authenticate si <account-izim>
kango <izim> <waktanimra> <sema> kyx <n> + body publish si
kaldy <izim> <waktanimra> [<kata...>] yank a release si
koja close koja, then close

ghazema echoes the digest on the response line so the client can verify while streaming. kango/kaldy require a prior successful kalit. cizujo exists so the client does not need a solver; when the server doesn't advertise it, the client walks ko besal recursively instead.

the kabuk archive

kabuk1\n
<path>\n<nbytes>\n<nbytes octets>      -- repeated
sampura\n                              -- terminator

rules: path is a relative POSIX path, UTF-8, <= 512 bytes, no leading /, no .. component, no backslash, no NUL. nbytes decimal ASCII. Entries sorted by path in byte order; directories implicit; no modes, no mtimes, no uid/gid, so the same tree always produces the same bytes and therefore the same digest. sema is SHA-256 over the whole octet stream including magic and terminator.

names, versions, constraints

  • izim: [a-z][a-z0-9_]*, ≤ 64 bytes. Must be a valid Oboe identifier because import foo uses the bare name. math, random and os are reserved (they are runtime built-ins, compiler/src/codegen.c:115-155).
  • waktanimra: MAJOR.MINOR.PATCH, optionally -<tag>, decimal.
  • Constraints (project.jsonc dependencies values): =X.Y.Z, >=X.Y.Z, ^X.Y.Z, *.

session rules

idle timeout 300 s: server sends koja and closes. the server MUST NOT send unsolicited lines other than this and the greeting. Malformed framing is wuwoji + close.
